### Shipping

**Verify each PR independently, then land only the contiguous verified run rooted at the bottom.** Read `references/playbooks/babysit.md` from this skill for merge-ready preparation. Execution requires an explicit grant to merge the named PRs; a style invocation, check request, or green CI does not grant it.

1. Resolve the verified repository and frozen bottom-to-top PR list. Launch one independent leaf verifier per PR where supported. Each gets exact PR/base/head SHAs, exclusive worktree, same real-surface scenarios, gates, no-code-write/publication restrictions and PASS/PASS+NOTES/FAIL with commands/evidence. A verifier must not have authored that PR. Diversity is optional and requires verified runners, never presumption. Post receipts only if separately authorized and read exact targets back. If independence is unavailable, return blocked for landing rather than self-authorizing a merge.

Use `delegate_task(tasks=[{"goal":"...","context":"..."}, ...])` for independent children. Each brief includes scope, evidence, exclusive output/worktree, verification and no delegation or user questions. Children share filesystems; read-only prompts are not sandboxes. Native children inherit the parent model or global pin: do not pass model/provider/readonly/background arguments or claim model diversity. Budget candidates, judges and synthesis together; obey confirmed concurrency and one-shot total-child limits. On exhaustion finish permitted lenses inline and label reduced independence, never retry or change global settings. For async delivery, finish independent work and end the turn; do not poll transcripts. Parent verifies returned artifacts and coordinates later waves. If an independent panel is explicitly required and unavailable, mark it blocked rather than substituting silently.
2. Compute the landable ceiling from the lowest unmerged PR upward. Both PASS and PASS+NOTES count only when notes do not contain a behavior defect. Stop at the first missing or failing verdict. A green descendant above a gap is not landable.
3. Record each verdict's head SHA, base SHA, and stable `git patch-id` for the base-to-head diff. Re-check against the current patch before landing. Unchanged patch-id preserves the code verdict but still requires fresh mergeability and CI at the current head. Changed patch requires reverification. For a change only in tests/docs/lint config, a lane may be reused only after comparing two builds at the verdict SHA with one at current head, classifying each difference as reproduced build noise or embedded SHA. Any non-noise difference invalidates it. A dev-server result without build output is never reusable. Matching commit messages or old green checks are not proof.
4. Fetch current trunk. Prepare only the bottom verified branch: rebase if necessary within grant, publish only to an authorized private branch with `--force-with-lease` after an `ls-remote` check if rewriting is explicitly covered, and retarget only that PR to trunk through `gh pr edit`. Read back the exact PR base/head after mutation and repeat step 3. Do not prepare, retarget or arm descendants.
5. Squash-merge only that PR if currently mergeable and authorized. If the grant explicitly includes merge-when-ready, arm auto-merge only for that PR while requirements finish. Use `gh pr merge <pr> --squash` or `--squash --auto` in the native shell with the resolved repository and the verified head pin where the installed CLI supports it. Never bypass required approvals. Read back `state,mergedAt,mergeCommit,headRefOid,baseRefName,mergeStateStatus,statusCheckRollup,autoMergeRequest`. AutoMergeRequest proves only one request, not queue safety or completed merge.
6. Bound the watch. Use bounded one-PR gh status/check passes and re-read exact PR state after every wait. Archived Bun helpers are reference-only, not the runtime. Merge-ready is not merged. Wait for MERGED or non-null mergedAt before advancing. CLOSED without merge, required failed/cancelled checks blocking with no auto-merge pending, or UNSTABLE/DIRTY with no auto-merge pending is failure. BLOCKED while checks or auto-merge are pending is not alone failure. A session/budget limit is an incomplete handoff, not a fabricated merge.
7. After each merge fetch trunk, confirm the actual merged commit is present, remove that PR from the frozen list, and inspect the new bottom's base/head/CI/patch-id. Do not assume the forge retargeted it. Repeat steps 3-6 for one PR at a time. Independent changes remain outside this chain.
8. Stop at the ceiling. Report the next unverified PR and the work needed to verify it. Extending the run needs a new verification pass and grant if outside the approved list.

**Reply:** verified run and ceiling, each verdict and verifier, what was armed and read back, actual merged commits, next gap and its required evidence.
