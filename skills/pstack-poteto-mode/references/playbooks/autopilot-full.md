### Autopilot-full

**Independent PR owners build; the parent owns verdicts and explicit shipping gates.** Use for an independent queue with an express grant naming publication and merge authority. Without merge authority choose Autopilot-stack. No workflow implies automatic merge.

Use `delegate_task(tasks=[{"goal":"...","context":"..."}, ...])` for independent children. Each brief includes scope, evidence, exclusive output/worktree, verification and no delegation or user questions. Children share filesystems; read-only prompts are not sandboxes. Native children inherit the parent model or global pin: do not pass model/provider/readonly/background arguments or claim model diversity. Budget candidates, judges and synthesis together; obey confirmed concurrency and one-shot total-child limits. On exhaustion finish permitted lenses inline and label reduced independence, never retry or change global settings. For async delivery, finish independent work and end the turn; do not poll transcripts. Parent verifies returned artifacts and coordinates later waves. If an independent panel is explicitly required and unavailable, mark it blocked rather than substituting silently.

1. Mark operator-owned items and preserve state-then-wait. A request to state a plan ends at the plan; execution starts only on explicit go. Operator-owned items stop at merge-ready. Name queue, budget, forbidden actions and always-pause gates.
2. Give each independent PR one scoped leaf owner in its own worktree/branch with a full consolidated lifecycle brief. Owners perform assigned leaf work; the coordinator runs additional exploration, review and verifier waves. Resolve verified `gh` once. Within the early checkpoint (about 15 minutes where practical), externalize the decisions trail and first local branch snapshot; push/open a ready PR early only if expressly authorized. Preserve hooks and evidence. No auto-install or bypass. Owners record every verifiable unit, pre-review commands run at committed head, code-ready head SHA, and later pushes that change the patch. The root tracks leaf ids, expected runtime, actual state and reports in `children.tsv`; there is no hidden owner child tree.
3. Parallelize independent disjoint PRs only. Branch from trunk for independent work; dependent work is merge-then-branch. A genuinely dependent split may use a short private stack with explicit topology ownership. Overlapping writes serialize, never share a checkout/index/ref.
4. At each code-ready patch run independent pstack-swarm lanes under the parent. Require a gates rerun at exact SHA, live load-bearing behavior on the real surface, a regression lane on current trunk, and two or more full-brief audit lanes (consumer parity, lifetimes/races, data/config safety as appropriate). If trunk lacks the feature, record that and gate diff-added behavior plus the user-visible end state, never invent a trunk result. Audit receipts, not PR-body claims. A live gap, failed lane or defect filed as a note prevents a clean verdict. Send all proven findings to a fresh owner in one consolidated fix brief, asking for a red test covering all affected sites or a repro receipt if no test can demonstrate it. The next head gets fresh lanes except those preserved by Shipping's patch-id/build-noise rule.

Native children stop with the parent/session. For separately authorized durable work use supported scheduling or `terminal(background=true, notify=true, persist_on_release=true)` for a real bounded job; never detached child claims or background sleep/poll loops. Discover cron/process tools before use, preserve explicit scope and leave actionable handoff evidence.
5. Self-proof, CI and bounded Babysit can run while independent root verification runs. Prepare merge only after verification starts. Rebase the authorized private branch onto current trunk before merge prep if required; publish rewrite only within explicit grant, with `--force-with-lease` and prior `ls-remote`. Report exact new head and wait for CI on it. Patch change invalidates the verdict. Immediately before merge fetch trunk, require a clean `git merge-tree` and check trunk-changed paths against PR paths plus CI-selection config. If either overlaps/conflicts, redo prep and required lanes. The parent countersigns only a clean current-patch verdict within merge grant. A fresh leaf shipping task may merge exactly that PR/head under Shipping, no broader authority. Read back actual merged state/commit. Operator-owned items remain waiting.
6. A genuinely new raise of a pinned gate or budget requires fresh parent countersign backed by proof and grant; absorb already-landed values as drift, not a new raise. Never bypass forge approval contracts. Audit at bounded session checkpoints. Hourly durable audit requires separately authorized cron/process, duration/delivery and cleanup, not a fictitious loop command. Re-read approved playbooks, branches, receipts and trails; count real commits/pushes/PR/check/store deltas. Runtime estimate with no updates is a reason to inspect, not proof a live child is stuck. Diagnose errors and confirm stop before replacement, or use isolated replacement scope. Preserve stalled scopes as gaps, never drop them. Sweep post-merge bot findings/reverts within scope. Account for every leaf even after the last merge.
7. On stop launch nothing, stop/cancel using available capability, confirm stopped writers before accepting replacement output, and checkpoint. Inspect supported lifecycle state after stop/session end; never presume workers survive. Approved independent processes must be explicitly managed. Never claim a zero-writes message was delivered without a real supported control channel and readback.

**Reply:** queue, owner role, actual status/head SHA per PR, verdicts and lanes, actual merges/readback, next fresh owner items, countersigns and grounds, operator gates, collected trail paths and gaps. Record the actual panel model policy; repeated same-model workers are not diversity. Claim diversity only when authorized, verified different-model execution actually ran.
