### Autopilot-stack

**Build and independently verify a linear base-branch chain; the operator lands it.** No owner or root merges, arms auto-merge or closes PRs in this playbook. Read Autopilot-full for the owner/trail and verification discipline, not its shipping authority.

Use `delegate_task(tasks=[{"goal":"...","context":"..."}, ...])` for independent children. Each brief includes scope, evidence, exclusive output/worktree, verification and no delegation or user questions. Children share filesystems; read-only prompts are not sandboxes. Native children inherit the parent model or global pin: do not pass model/provider/readonly/background arguments or claim model diversity. Budget candidates, judges and synthesis together; obey confirmed concurrency and one-shot total-child limits. On exhaustion finish permitted lenses inline and label reduced independence, never retry or change global settings. For async delivery, finish independent work and end the turn; do not poll transcripts. Parent verifies returned artifacts and coordinates later waves. If an independent panel is explicitly required and unavailable, mark it blocked rather than substituting silently.

1. Use one leaf owner per independent change, exclusive worktree and branch, with full goal/scope/acceptance/verify/report/standing-orders brief. The root flattens every additional worker/review/verifier wave. Early decisions trail and branch snapshot are required; ready PR before self-proof is allowed only within explicit publication grant. Keep hooks, skeptical bot triage, applicable simplify-code/requesting-code-review and pstack-no-comments. Run bounded Babysit only as assigned. The root maintains `children.tsv`; owners cannot spawn grandchildren.

Native children stop with the parent/session. For separately authorized durable work use supported scheduling or `terminal(background=true, notify=true, persist_on_release=true)` for a real bounded job; never detached child claims or background sleep/poll loops. Discover cron/process tools before use, preserve explicit scope and leave actionable handoff evidence.
2. Audit at bounded session checkpoints with current playbook, exact PR/branch/check deltas and decision trails. An hourly durable tick is separately authorized cron/process with duration, delivery and stop conditions. No fictitious loop command or persistent worker assumed from delegation. Inspect suspected stalls and establish stop before replacing a writer; preserve missing scopes as gaps.
3. Hold operator gates. Stating the plan is not go. Stop starts no new work and safely checkpoints actual on-disk state. Preserve user-owned interaction review gates with screenshots/video where applicable.
4. Owner reports code-ready and STACK-READY with exact head SHA. Root runs every Autopilot-full verification lane at that patch, including gates, live regression against trunk and at least two audits. Return every proven defect in a consolidated fresh fix round. Nothing enters the chain without a clean current-patch verdict; a gap never counts as pass.
5. Append only after a clean verdict, in verified or operator-specified order. No merges, auto-merge or closes. Exactly one root topology writer. Owners push only their own authorized branches and report tip/base/intended parent.
6. To append, fetch the exact parent tip, rebase child in its exclusive worktree only within grant, and push any rewrite with `--force-with-lease` only after an `ls-remote` check and explicit rewrite authorization. Root PR targets trunk, each child targets its parent branch. Create/retarget with verified `gh pr create --base <parent-branch>` or `gh pr edit <pr> --base <parent-branch>`, read back exact base/head/draft state. No Graphite registration or Origin requirement.
7. Absorb trunk drift bottom-up as scoped topology work. Owner resolves conflicts in its slice, root verifies and publishes only within grant. Every changed head invalidates its verdict unless Shipping's precise patch-id/build-noise rule preserves a lane; CI and mergeability always refresh. Newly raised pinned budgets require fresh proof/countersign. Already-landed values are drift, not permission to raise limits.
8. Deliver one linear reviewable bottom-up chain. Put verdict receipts in PR body/comment only when posting is authorized, then read back. Otherwise deliver local receipts with PR links. The operator reviews and lands with their own clicks or a separate Shipping grant.

**Choosing:** full for genuinely independent PRs with explicit landing authority; stack for coupled/sequenced work or operator review/withheld merge authority.

**Reply:** root/tip links, each exact-head verdict, chain order, evidence paths, pending operator gates and parked/excluded work with reasons. Use bullets on Discord.
